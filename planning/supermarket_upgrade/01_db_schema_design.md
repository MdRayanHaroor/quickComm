# DB Schema Design — Supermarket Upgrade

> **Priority:** This is Phase 1 — everything else depends on this.

---

## Design Principles

1. **Normalize what varies** — categories, brands, units of measure are their own tables
2. **Variants are first-class** — one product can have many SKUs (sizes/weights/packs)
3. **Snapshot order data** — order_items must store full product name + price at time of purchase (never break historical orders)
4. **India-specific** — GST, MRP, INR pricing, Indian address format
5. **Backwards compatible** — existing orders data must not break; use additive migrations
6. **Supabase Storage for images** — not raw URLs

## Complete New Schema

### Table 1: `categories` (NEW)

```sql
CREATE TABLE public.categories (
  id        bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name      text NOT NULL,
  slug      text NOT NULL UNIQUE,           -- URL-safe: "dairy-eggs", "beverages"
  parent_id bigint REFERENCES public.categories(id) ON DELETE SET NULL,
  image_url text,                           -- Category banner/icon in Supabase Storage
  sort_order int DEFAULT 0,                -- For manual ordering in UI
  is_active  boolean DEFAULT true,
  created_at timestamptz DEFAULT now() NOT NULL
);

-- Self-referencing for subcategories:
-- Beverages (id=1)
--   Cold Drinks (parent_id=1)
--   Juices (parent_id=1)
-- Dairy & Eggs (id=2)
--   Milk (parent_id=2)
--   Curd & Yoghurt (parent_id=2)

CREATE INDEX idx_categories_parent ON public.categories(parent_id);
CREATE INDEX idx_categories_slug ON public.categories(slug);
```

### Table 3: `products` (MAJOR RESTRUCTURE)

> **Migration Strategy:** ALTER existing table (additive) to avoid data loss.

```sql
-- New columns to ADD to existing products table:
ALTER TABLE public.products
  ADD COLUMN IF NOT EXISTS slug text UNIQUE,
  ADD COLUMN IF NOT EXISTS brand_id bigint REFERENCES public.brands(id) ON DELETE SET NULL,
  ADD COLUMN IF NOT EXISTS category_id bigint REFERENCES public.categories(id) ON DELETE SET NULL,
  ADD COLUMN IF NOT EXISTS tags text[] DEFAULT '{}',           -- searchable tags: ['organic', 'gluten-free']
  ADD COLUMN IF NOT EXISTS images text[] DEFAULT '{}',         -- array of Supabase Storage URLs
  ADD COLUMN IF NOT EXISTS gst_rate numeric DEFAULT 0,         -- GST %: 0, 5, 12, 18, 28
  ADD COLUMN IF NOT EXISTS updated_at timestamptz DEFAULT now() NOT NULL;

-- Keep existing columns but change defaults/types:
-- name, description → keep
-- price → will be MOVED to product_variants (keep for backward compat but deprecate)
-- category → keep as fallback text, but category_id is the source of truth
-- size → will be MOVED to product_variants (keep for compat)
-- image_url → keep for compat, but images[] is the real one
-- is_available → move availability to variant level (keep product-level as master switch)
```

> **Why keep old columns?** The existing `order_items` reference `product_id` and display product info. Dropping columns would require a full data migration of historical orders first. We keep old columns as "deprecated" and stop writing to them after the migration is complete.

### Table 4: `product_variants` (NEW — the most important new table)

```sql
CREATE TABLE public.product_variants (
  id              bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  product_id      bigint REFERENCES public.products(id) ON DELETE CASCADE NOT NULL,

  -- Identity
  sku             text UNIQUE,                    -- e.g., "AMUL-MILK-500ML-001"
  barcode         text,                           -- EAN-13 / QR for scanning

  -- What makes this variant different
  variant_name    text NOT NULL,                  -- "500 ml", "1 kg", "Pack of 6"
  unit_value      numeric,                        -- 500, 1, 6
  unit_type       text,                           -- 'ml' | 'l' | 'g' | 'kg' | 'pcs' | 'pack'

  -- Pricing
  mrp             numeric NOT NULL,               -- Maximum Retail Price (printed on pack)
  selling_price   numeric NOT NULL,               -- Our actual selling price (≤ MRP)
  -- discount = mrp - selling_price (computed, no need to store)

  -- Inventory
  stock_quantity  int DEFAULT 0,
  low_stock_alert int DEFAULT 10,                 -- Alert admin when stock < this
  is_available    boolean DEFAULT true,           -- Can be ordered right now?

  -- Display
  image_url       text,                           -- Variant-specific image (optional override)
  sort_order      int DEFAULT 0,                  -- Which variant is shown first (default selection)

  created_at      timestamptz DEFAULT now() NOT NULL,
  updated_at      timestamptz DEFAULT now() NOT NULL
);

CREATE INDEX idx_variants_product ON public.product_variants(product_id);
CREATE INDEX idx_variants_sku ON public.product_variants(sku) WHERE sku IS NOT NULL;
CREATE INDEX idx_variants_available ON public.product_variants(is_available) WHERE is_available = true;

-- Example: Amul Milk product with 3 variants:
-- variant 1: "500 ml", mrp=28, selling_price=27, stock=150
-- variant 2: "1 L",    mrp=54, selling_price=52, stock=80
-- variant 3: "2 L",    mrp=102, selling_price=99, stock=30
```

### Table 5: `order_items` (MODIFY — add variant support)

```sql
ALTER TABLE public.order_items
  ADD COLUMN IF NOT EXISTS variant_id bigint REFERENCES public.product_variants(id) ON DELETE SET NULL,
  ADD COLUMN IF NOT EXISTS product_name_snapshot text,   -- "Amul Milk 1 L" — never breaks
  ADD COLUMN IF NOT EXISTS variant_name_snapshot text,   -- "1 L" — never breaks
  ADD COLUMN IF NOT EXISTS mrp_at_time numeric,          -- MRP at time of purchase
  ADD COLUMN IF NOT EXISTS discount_at_time numeric DEFAULT 0; -- mrp - selling_price at time
-- price_at_time already exists — this is the selling_price at time of purchase
```

## RLS Policy Design

### `categories` — Public read, admin write
```sql
-- Anyone can read categories
CREATE POLICY "categories_read_all" ON categories FOR SELECT USING (true);
-- Only admins can write
CREATE POLICY "categories_admin_insert" ON categories FOR INSERT
  WITH CHECK (EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'admin'));
CREATE POLICY "categories_admin_update" ON categories FOR UPDATE
  USING (EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'admin'));
CREATE POLICY "categories_admin_delete" ON categories FOR DELETE
  USING (EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'admin'));
```

### `product_variants` — Public read, admin write
```sql
-- Same pattern as categories
CREATE POLICY "variants_read_all" ON product_variants FOR SELECT USING (true);
CREATE POLICY "variants_admin_write" ON product_variants FOR ALL
  USING (EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'admin'));
```

### `customer_addresses` — Users own their own
```sql
CREATE POLICY "addresses_own" ON customer_addresses
  FOR ALL USING (auth.uid() = user_id);
```

## Data Migration — Existing Products

After creating the new tables, we need to migrate existing restaurant-style products:

```sql
-- 1. Create a "Uncategorized" category as safety net
INSERT INTO categories (name, slug) VALUES ('Uncategorized', 'uncategorized')
  ON CONFLICT (slug) DO NOTHING;

-- 2. For each existing product, create a default variant
INSERT INTO product_variants (product_id, variant_name, mrp, selling_price, stock_quantity, is_available)
SELECT
  id,
  COALESCE(size, 'Standard'),  -- Use existing size or 'Standard'
  price,                        -- mrp = existing price
  price,                        -- selling_price = same (no discount by default)
  999,                          -- default high stock for existing items
  is_available
FROM products;

-- 3. Set category_id using text category mapping (best effort)
UPDATE products SET category_id = (SELECT id FROM categories WHERE slug = 'uncategorized')
WHERE category_id IS NULL;
```

## Key Design Decisions & Rationale

| Decision | Rationale |
|---|---|
| `product_variants` as separate table | Industry standard (Shopify, Swiggy Instamart do this). Avoids denormalization. One product = many SKUs |
| Keep old `products.price` and `products.category` | Backward compat — don't break existing orders that still JOIN on products directly |
| `images text[]` array not a separate table | For a kirana store scale (10k-50k products), array on the product row is fine. A separate media table is overkill at this stage |
| `slug` on categories | Required for clean URLs: `/category/dairy-eggs` |
| `mrp` stored separately from `selling_price` | Indian legal requirement. Also enables showing "₹54 ₹52 — 4% off" badges |
| Snapshot fields in `order_items` | If a product is deleted or renamed, old order history still makes sense |
| `gst_rate` on products | Indian GST law requires correct rate per product category. 0% for staples, 5% for packaged food, 12%/18% for others |
